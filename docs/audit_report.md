# 統合レポート（監査指摘の原因分析）

- 作成日: 2026-05-03
- 作成者: PM
- 対象: 既存 `audit_report.md` の全指摘
- 対象フェーズ: `docs/roadmap.md` M5（最終統合監査）
- 総合判定: **REJECT（是正完了まで解除不可）**

## 1. 統合サマリ

既存監査で確認された重大指摘は「Validator入力制約の不一致」である。  
本件は単一記述ミスではなく、要件の正本管理・反映手順・レビュー観点の3層で統制が抜けた結果として発生した。

## 2. 指摘事項（統合）

1. `docs/plan.md` の必須要件は `requirement + diff + test evidence`。
2. 一方、`docs/roadmap.md` M5の監査入力定義が `requirement + diff` へ縮退。
3. 同縮退が「実施内容」「完了条件」の双方に転記され、不整合が固定化。

## 3. 原因分析

### 3.1 直接原因

- M5更新時、入力制約の参照元が `plan.md` ではなく要約解釈寄りの運用となった。
- その結果、`test evidence` が削除された定義がそのまま確定した。

### 3.2 根本原因（管理プロセス）

- 文書間の優先順位（正本）が明文化されていない。
- Roadmap更新時に「要件同値チェック（planとroadmapの一致確認）」が必須工程化されていない。
- 監査成立条件（証拠必須）がレビュー項目としてチェックリスト化されていない。

### 3.3 組織的原因（運用設計）

- 監査観点が担当者知識依存で、文書品質が人依存になっている。
- 「証拠欠落時は自動不合格」という判定規則が、工程制御として実装されていない。

## 4. 影響評価

- 監査判定の客観性・再現性が低下。
- 再監査で追加確認が発生し、手戻りコストが増大。
- Builder/Validator分離運用の信頼性が低下。

## 5. 是正措置（必須）

1. `docs/roadmap.md` M5の入力定義を `requirement + diff + test evidence` に修正する。
2. M5完了条件に「`test evidence` 欠落時は未完了（REJECT）」を明記する。
3. M5記述の「実施内容」「完了条件」の両方で同一制約を明示し、記述差分を解消する。

## 6. 再発防止策（恒久）

1. 文書正本ルールを明文化する。  
   優先順位: `plan.md` > `roadmap.md` > `reference_standards.md`
2. 更新レビューに以下3点を必須化する。  
   `入力3点セット一致` / `完了条件同値` / `欠落時の判定規則`
3. M5更新時の監査チェックリスト添付を必須化する。

## 7. 完了判定条件（本件クローズ条件）

- 是正措置3点の文書反映完了。
- 再監査で不一致ゼロを確認。
- `REJECT_TO_PM` を解除し、監査ステータスを更新。

## 8. 最終結論

現時点では監査成立条件を満たしていないため、判定は **REJECT** を維持する。  
解除は「是正措置の反映完了」と「再監査合格」の両方達成時のみ可能。
