# 統合レポート（監査指摘の原因分析）

- 作成日: 2026-05-03
- 作成者: PM
- 対象: これまでの `audit_report.md` 指摘事項
- 対象フェーズ: `docs/roadmap.md` M5（最終統合監査）
- 総合判定: **REJECT（是正完了まで維持）**

## 1. 統合サマリ

過去指摘を統合すると、主要論点は一貫して「監査入力要件の欠落（`test evidence` 抜け）」である。  
この欠落は単発ミスではなく、**要件正本の不明確さ**、**更新時同値確認の欠如**、**レビュー基準の未実装**が連鎖して発生した。

## 2. 指摘統合（事実）

1. `docs/plan.md` では監査入力を `requirement + diff + test evidence` と定義。
2. `docs/roadmap.md` M5 では `requirement + diff` に縮退。
3. 縮退定義が M5 の「実施内容」「完了条件」双方に反映され、文書内で固定化。
4. 結果として、証拠なしでも通過可能に見える運用余地が発生。

## 3. 原因分析

### 3.1 直接原因

- M5 更新時に `plan.md` の定義を完全転記せず、要件が2点化された。
- レビュー時に `test evidence` 欠落が不備として検出されなかった。

### 3.2 根本原因（プロセス）

- 文書間の正本優先順位が運用規約として固定されていない。
- `plan` と `roadmap` の要件同値チェックが、更新ゲートに組み込まれていない。
- 「証拠必須」の監査成立条件が、レビューの必須チェック項目になっていない。

### 3.3 管理原因（統制）

- 判定規則が担当者判断に依存し、機械的な不合格条件が未定義。
- 文書差分レビューが体裁中心になり、意味差分（要件欠落）検出が弱い。

## 4. 原因連鎖（Causal Chain）

1. 正本ルール不在
2. 更新時同値チェック未実施
3. `test evidence` 欠落定義が roadmap に定着
4. 完了条件も同様に縮退
5. 監査の再現性・客観性が低下
6. REJECT 判定と是正ループが発生

## 5. 影響評価

- 監査品質: 判定の客観性・再現性が低下。
- 工程: 再監査・再説明が増加し、手戻りコストが拡大。
- 組織: Builder/Validator 分離統制の信頼性が低下。

## 6. 是正措置（必須）

1. `docs/roadmap.md` M5 の入力定義を `requirement + diff + test evidence` に修正。
2. M5 完了条件へ「`test evidence` 欠落時は未完了（REJECT）」を明記。
3. M5 の「実施内容」と「完了条件」で同一制約を明示し、差分を解消。

## 7. 再発防止（恒久）

1. 正本優先順位を明文化し固定運用する。  
   `plan.md` > `roadmap.md` > `reference_standards.md`
2. 更新レビューの必須チェックを定義する。  
   `入力3点セット一致` / `完了条件同値` / `欠落時の判定規則`
3. M5 更新時は監査チェックリスト添付を必須化する。
4. 監査ゲートに「証拠未添付なら自動 REJECT」を明文化する。

## 8. クローズ条件

- 是正措置 1-3 の文書反映完了。
- 再監査で不一致ゼロ。
- `REJECT_TO_PM` の解除と監査ステータス更新。

## 9. 最終結論

現時点では監査成立条件を満たしていないため、判定は **REJECT** を維持する。  
解除条件は「是正措置の反映完了」および「再監査合格」の両達成のみとする。
