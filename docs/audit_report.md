## 1. 指摘事項（基準違反）

### 指摘1: 既知再発2メソッドの完了条件が計画基準より弱い
- 失敗箇所: `docs/roadmap.md` M1（成果物/完了条件）
- 違反基準:
  - `docs/plan.md` 4.1/4.2 では、`_run_container` と `_show_create_env_dialog` について以下を完了条件として**明示必須**としている。
    - UseCase呼び出し+UI表示更新以外を保持しないこと
    - Domain/Infrastructure実装型への直接import 0件
    - 「不足import→候補生成→作成→再評価」を1 UseCase境界で完結
    - Dynamic Refresh（再起動不要反映）
- 現状:
  - `roadmap.md` は「責務分離完了」「専用監査チェックリスト保存」に留まり、上記の検証可能な完了条件が明文化されていない。
- 影響:
  - PM工程での完了判定が曖昧化し、過去差し戻し要因（UI責務混在/境界逸脱）の再発リスクが残る。
- 修正指示:
  - M1完了条件へ、`plan.md` 4.1/4.2 の必須完了条件をそのまま検証項目として追加すること。

### 指摘2: 構造ゲートの必須条件が計画基準より不足
- 失敗箇所: `docs/roadmap.md` 3.1 構造ゲート
- 違反基準:
  - `docs/plan.md` 6章の構造ゲート必須項目:
    - Port経由率100%
    - 内側層（UseCase/Domain）から外側層（UI/Infrastructure）への直接依存0件
    - 既知再発ポイント監査（2メソッド）違反0件
- 現状:
  - `roadmap.md` 3.1 には上記3項目の明示がない（または禁止依存0に包含させた解釈依存）ため、監査判定の客観性が下がる。
- 影響:
  - EMCSの「依存違反」評価が運用者解釈に依存し、Builder/Validator分離監査で判定ぶれが発生する。
- 修正指示:
  - 3.1へ当該3項目を独立行として追記し、測定方法（importグラフ/責務チェックリスト）を明記すること。

### 指摘3: 標準条項トレーサビリティの成果物定義が不足
- 失敗箇所: `docs/roadmap.md` 全体（M1成果物の記述粒度）
- 違反基準:
  - `docs/plan.md` Phase A 完了条件で「標準条項トレーサビリティマトリクス」を監査可能形式で作成必須。
  - `docs/reference_standards.md` は逸脱ゼロを要求。
- 現状:
  - マトリクス作成は記載されているが、監査証跡としての保存先/更新責任/フェーズ遷移前チェックが未定義。
- 影響:
  - 「作成したが監査で参照不能」の状態を許し得る。
- 修正指示:
  - M1に「保存先ファイル」「更新タイミング」「遷移ゲートでの照合手順」を追加すること。
