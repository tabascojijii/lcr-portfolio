# 統合レポート（監査指摘の原因分析）

- 作成日: 2026-05-03
- 作成者: PM
- 対象: これまでの `audit_report.md` 指摘
- 対象フェーズ: `docs/roadmap.md` M5（最終統合監査）
- 総合判定: **REJECT（是正完了まで維持）**

## 1. エグゼクティブサマリ

過去指摘の共通論点は、監査入力要件から `test evidence` が欠落した点である。  
本件は記載漏れではなく、要件管理・更新レビュー・判定統制の3層で管理不備が重なって発生した構造問題である。

## 2. 指摘統合（確認済み事実）

1. `docs/plan.md` は監査入力を `requirement + diff + test evidence` と定義している。
2. `docs/roadmap.md` の M5 は `requirement + diff` へ縮退している。
3. この縮退は M5 の「実施内容」と「完了条件」の両方に反映されている。
4. 結果として、証拠未添付でも通過可能に見える運用余地が残っている。

## 3. 原因分析

### 3.1 直接原因

- M5 更新時に、`plan.md` の3点要件が `roadmap.md` へ完全反映されなかった。
- レビューで `test evidence` 欠落を検知する明示チェックがなく、見逃しが発生した。

### 3.2 根本原因（プロセス）

- 文書間の正本優先順位が運用ルールとして固定されていない。
- `plan` と `roadmap` の同値確認が更新ゲートに組み込まれていない。
- 監査成立条件（証拠必須）がレビュー必須項目として定義されていない。

### 3.3 管理原因（ガバナンス）

- 判定ルールが担当者判断に依存し、不合格条件の機械判定が設計されていない。
- 差分レビューが記述体裁寄りで、要件の意味差分を検知しにくい運用になっている。

## 4. 原因連鎖（Causal Chain）

1. 正本ルール未定義
2. 更新時の同値チェック不在
3. M5 入力要件が2点へ縮退
4. 完了条件も同様に縮退
5. 監査判定の客観性・再現性が低下
6. REJECT と是正ループが継続

## 5. 影響評価

- 品質影響: 監査判定の妥当性と再現性が低下。
- 工程影響: 再監査・再説明が増加し、手戻りコストが増大。
- 統制影響: Builder/Validator 分離統制への信頼が毀損。

## 6. 是正措置（必須・短期）

1. `docs/roadmap.md` M5 の入力定義を `requirement + diff + test evidence` に修正する。
2. M5 完了条件に「`test evidence` 欠落時は未完了（REJECT）」を明記する。
3. M5 の「実施内容」と「完了条件」を同一制約で統一し、記載差分を解消する。

## 7. 再発防止（恒久）

1. 正本優先順位を明文化して固定する。  
   `plan.md` > `roadmap.md` > `reference_standards.md`
2. 更新レビューに以下3項目を必須化する。  
   `入力3点セット一致` / `完了条件同値` / `欠落時判定規則`
3. M5 更新時に監査チェックリスト添付を必須化する。
4. 監査ゲートに「証拠未添付は自動 REJECT」を運用規則として実装する。

## 8. クローズ条件

- 是正措置（6.1-6.3）の文書反映完了
- 再監査で不一致ゼロ
- `REJECT_TO_PM` 解除および監査ステータス更新

## 9. 最終結論

2026-05-03 時点では監査成立条件を満たしていないため、判定は **REJECT** を維持する。  
解除条件は「是正措置の反映完了」および「再監査合格」の同時達成とする。
