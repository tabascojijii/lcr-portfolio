# 監査報告書（Plan Audit）

- 監査対象: `docs/plan.md`
- 絶対基準: `docs/reference_standards.md`
- 監査日: 2026-05-05
- 総合判定: **REJECT_TO_ARCHITECT**

## 指摘事項（重大度順）

1. **[重大] Builder/Validator 分離要件の未規定**
- 基準: 1章「Builder/Validatorの分離」
- 事実: `docs/plan.md` には、監査が「要件とDiffのみ」を根拠に実施される運用制約が明文化されていない。
- リスク: 実装側思考プロセス混入により、監査の独立性と敵対的レビュー強度が低下し、差し戻し品質が不安定化する。
- 修正指示: 監査運用節を追加し、(a) 監査入力は要件・差分・証跡のみに限定、(b) 実装者の意図説明は判定根拠に使わない、を必須ルールとして明記すること。

2. **[重大] 処方的エラーハンドリング要件の未充足**
- 基準: 1章「処方的なエラーハンドリング」
- 事実: `docs/plan.md` は `REJECT_TO_ARCHITECT` / `REJECT_TO_IMPLEMENT` の分類はあるが、差し戻しメッセージに必須な「失敗箇所・違反制約・具体的修正ヒント」の出力フォーマットが規定されていない。
- リスク: 差し戻しが抽象化し、同一不具合の再発ループ（再差し戻し）を防止できない。
- 修正指示: 差し戻しテンプレート（必須項目固定）を plan に追加すること。
  - 必須項目: `failure_location`, `violated_standard`, `evidence`, `required_fix`, `retest_condition`

3. **[中] PyQt/PySide シグナル・スロット命名規約の欠落**
- 基準: 4章「シグナル・スロットの命名規則」
- 事実: `docs/plan.md` は Humble Object / 依存方向 / Port は扱うが、`dataChanged` 形式のシグナル、動詞形式スロットの命名規約が未記載。
- リスク: UI層の一貫性が崩れ、将来の保守・レビューで規約逸脱検知が困難になる。
- 修正指示: UI規約節に命名ルールと lint/レビュー観点を追加すること。

## 適合している主要項目

- 依存方向制約、Port経由強制、循環依存ゼロ化方針は明記済み。
- 監査証跡の相対パス・ハッシュ完全化・`image_digest`/`git_commit` 記録は明記済み。
- EOLコンテナ再現性4要件（digest固定、EOLミラー、constraints、multi-stage）は明記済み。

## 結論

`docs/plan.md` は絶対基準の一部を満たすが、監査ガバナンス必須要件（分離運用・処方的差し戻し）およびUI命名規約が未規定のため、現時点では承認不可。Architect に差し戻し、上記3点を反映した改訂版の再提出を要求する。
