# LCR Project Reference Standards (業界標準およびアーキテクチャ規約)

本ドキュメントは、LCR (Legacy Code Reviver) プロジェクトにおけるAIエージェント（Architect, PM, Implementer, Auditor）が遵守すべき絶対的な技術基準である。Auditorは本基準からの逸脱を一切許容せず、違反を発見した場合は客観的な根拠と共にNG判定（REJECT）を出さなければならない。

## 1. 監査およびマルチエージェント・ガバナンス標準
AIエージェント間のサイレントな要件逸脱や無限ループを防ぐため、以下の評価・実装基準を厳守する。

* **客観的アーキテクチャ評価 (EMCSモデル):** 監査役(Auditor)は、主観的な「好み」ではなく、信頼性と影響度に基づいた客観的メトリクス（例：単一責任の原則違反、サイクロマティック複雑度の超過など）でNG判定を下すこと[cite: 3]。
* **Builder/Validatorの分離:** 実装役と思考プロセスを共有せず、要件と生成された差分(Diff)のみから敵対的かつ厳格にレビューを行うこと[cite: 3]。
* **処方的なエラーハンドリング:** 差し戻し（REJECT）を行う際は、単なる「失敗」の通知ではなく、失敗箇所、違反した制約、具体的な修正指示（ヒント）を含めた処方的なメッセージを返すこと[cite: 3]。

## 2. EOLスタックのコンテナ化およびビルド再現性標準 (Docker)
Python 2.7やOpenCV 2.4などのEOL技術を、エンタープライズ品質で100%確実に再現するためのコンテナ構築基準。

* **ダイジェストによる完全固定:** `Dockerfile`の `FROM` 句には、可変のタグ（例: `python:2.7-slim`）ではなく、必ずSHA256ダイジェスト（例: `@sha256:c123...`）を使用し、ベースイメージの不変性を保証すること[cite: 4]。
* **アーカイブ・リポジトリへのリダイレクト:** EOLとなったOSのパッケージ取得では、標準ミラーではなくアーカイブサーバー（Ubuntuなら `old-releases.ubuntu.com`、Debianなら `archive.debian.org`）へAPTソースを適切に書き換えること[cite: 4]。
* **pipのデッドロック回避:** 古いパッケージの依存関係解決におけるバックトラッキング（無限ループ）を防ぐため、`constraints.txt` を用いて探索範囲を厳格に制限すること[cite: 4]。
* **マルチステージビルドの強制:** OpenCV等のC++ライブラリをビルドする際は、ビルド環境（コンパイラ等）と実行環境を明確に分離し、実行ステージにはビルド済みバイナリとランタイムのみを配置すること[cite: 4]。

## 3. データ完全性と監査証跡 (Data Integrity)
計算の再現性を法的証拠レベルに引き上げるため、ALCOA++原則に基づく監査証跡を実装する。

* **環境とコードのハッシュ記録:** 実行ログには、コンテナイメージのダイジェスト値と、実行時のGitコミットハッシュ（`git rev-parse HEAD`）を必ず記録し、不変性を担保すること[cite: 1, 4]。
* **相対パスによるポータビリティ:** ログファイルやスクリプト内のパス指定は、他環境での検証可能性を維持するため、すべてプロジェクトルートからの相対パスで記述すること[cite: 1]。
* **ハッシュによる改ざん検知:** すべての入出力データ、パラメータファイル、および実行ログ自体に暗号学的ハッシュ関数（SHA-256等）を適用し、改ざんを検知可能な状態にすること[cite: 1]。

## 4. PyQt / PySide モダンUIアーキテクチャ標準
GUIアプリケーションにおけるビジネスロジックの汚染を防ぎ、自動テストを可能にするための設計規約。

* **Humble Object パターンの適用:** View（UIウィジェット）は極限までロジックを持たない「謙虚な」オブジェクトとし、複雑な計算やフォーマット処理はPresenterやViewModel側に移譲すること[cite: 2]。
* **クリーンアーキテクチャと依存の方向:** UI層は最も外側のレイヤーであり、内側のビジネスルール（Entities, Use Cases）がUIフレームワーク（Qt）に依存してはならない[cite: 2]。
* **インターフェースによる規律:** クラス間の通信は、`abc.ABC` や `typing.Protocol` を用いた抽象基底クラス（インターフェース）を通じて行い、AIエージェントによる実装の抜け漏れを防ぐこと[cite: 2]。
* **シグナル・スロットの命名規則:** シグナルは「過去分詞形（例: `dataChanged`）」、スロットは「動作を示す動詞（例: `update_display`）」を用いて、一貫性のある命名を行うこと[cite: 2]。
