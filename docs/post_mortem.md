# 事後分析レポート（Post Mortem）

- 作成日: 2026-05-04
- 対象事象: Phase 6.1 における監査差し戻しの反復（実質的な無限ループ）
- 根拠資料: `docs/audit_report.md`

## 1. 事象の定義

`docs/audit_report.md` の総合判定は `REJECT_TO_IMPLEMENT` だが、差し戻し理由の実体は以下3点であり、いずれも「コード欠陥」より前段の「設計・要件定義不足」に属する。

1. AC6.1-5 未充足
- importグラフの抽出手順と具体的一覧が欠落し、監査可能な証拠形式が未定義。

2. AC6.1-6 未充足
- 変更影響テストの実施手順（シナリオ・期待影響範囲・合否条件）が未定義。

3. AC6.1-7 未充足
- 合否指標の固定閾値（数値ゲート）が未定義。

## 2. 無限ループの構造

反復したループは次の通り。

1. 設計成果物で監査証拠の仕様が曖昧なまま実装に着手
2. 実装は進むが、監査で「証拠形式・判定基準不足」として不合格
3. 不合格理由が設計不備にもかかわらず実装側へ再投入
4. 同一条件のため再監査でも同種理由で不合格

これは不具合修正ループではなく、設計未確定のまま実装工程を回したことによるプロセスループである。

## 3. 根本原因（Root Cause）

### RC-1: 受け入れ基準の「検証可能な形式」が設計に埋め込まれていない

AC6.1-5/6/7 は「何を作るか」だけでなく「どう証明するか」を要求している。今回不足したのは実装コードではなく、以下の設計要素。

- importグラフの抽出手順定義
- 違反一覧の出力フォーマット定義
- 変更影響テスト手順テンプレート
- 数値ゲート（しきい値）の固定

つまり、品質判定の契約がArchitect成果物として先に固定されていなかった。

### RC-2: アーキテクチャ境界の評価方法が未設計

監査観点として「UI責務混在違反」は認識されている一方、判定を機械的に再現する評価手順が不十分だった。

- 境界違反をどう検知し、どの形式で記録するかが不足
- 「違反の存在報告」と「違反ゼロを証明する検証」が分離されていない

結果として、実装が正しくても監査で合格不能な状態が生じた。

### RC-3: 差し戻しルーティング規則の不整合

監査結果の表示上は `REJECT_TO_IMPLEMENT` だが、未達の内容は設計再定義が必要な項目である。ルーティングと原因層が一致していないため、是正アクションが誤って反復した。

## 4. 是正提言（責任層の再設定）

本件は Implementer への追加実装指示で解決しない。主担当は Architect とし、上位設計からやり直す。

必須提言:

1. Architect起点で Phase 6.1 の受け入れ契約を再定義する
- AC6.1-5: importグラフ抽出コマンド、対象範囲、出力項目、違反分類キーを固定
- AC6.1-6: 変更影響テストのシナリオ雛形、期待影響範囲、合否判定式を固定
- AC6.1-7: 合否閾値を数値で固定（例: 禁止依存0、循環依存0、UI業務ロジック0、境界テストPass率100%）

2. 監査可能性を成果物テンプレートとして先に固定する
- `artifacts/architecture_decoupling_assessment.md` と `artifacts/refactoring_proposal.md` に必須セクションを規定
- 「手順」「実測一覧」「件数サマリ」「判定」の4点セット欠落を自動で不合格化

3. 差し戻しルーティングを原因層基準に変更する
- 設計欠落: `REJECT_TO_ARCHITECT`
- 実装欠陥: `REJECT_TO_IMPLEMENT`

## 5. 再発防止策

1. 実装着手条件（Definition of Ready）を追加
- 受け入れ基準が「検証手順」「証拠フォーマット」「数値ゲート」まで確定していない限り、Implementerへ投入しない。

2. 監査前ゲートの追加
- 成果物セルフチェックで AC6.1-5/6/7 の形式要件を機械的に検証してから監査へ送る。

3. 指標の一元管理
- 閾値・判定式・出力フォーマットを requirements 系ドキュメントに集約し、各成果物から参照のみ許可する。

## 6. 結論

無限ループの根本原因は、実装品質ではなく上位設計（アーキテクチャ境界評価と受け入れ契約定義）の不足である。したがって対処は Implementer への追加実装ではなく、Architect が設計基準を再構築してから工程を再開することが必要である。
